# 📘 Roadmap.md

**GameDesk Development Roadmap**  
**Версия:** 2.3

## 🎯 Цель проекта
Создание системы GameDesk:
- ESP32 + TFT 2.8" ST7789V (тонкое клиентское UI-устройство)
- GameDesk.exe (ПК-ядро — вся бизнес-логика)
- USB Serial (протокол обмена с групповыми пакетами)

---

## 🧠 Принцип разработки
**WORKING → STABLE → BEAUTIFUL → SMART**

## ⚙️ Базовые правила

### Обязательно:
- сначала рабочая система
- затем стабильность
- затем UI/UX
- затем расширение функционала

### Запрещено:

- изменение протокола без версии `VER`

---

## 🧩 Архитектурные слои

1. **GameDesk.exe (ПК)**  
   - process monitoring  
   - session tracking (**время сессии считает только ПК**)  
   - telemetry (CPU/GPU/RAM)  
   - protocol builder (одиночные и групповые пакеты)  
   - serial sender  
   - statistics storage (`games.json`)

2. **ESP32**  
   - serial receiver (**буфер ≥1024 байт**)  
   - packet validation (**парсинг только после `>`**)  
   - parser (включая групповые `<LIST>...</LIST>`)  
   - UI state machine  
   - button handling (5 кнопок, антидребезг)  
   - partial screen updates  
   - **никогда не хранит список игр как источник истины**

3. **Protocol Layer**  
   - `VER` validation  
   - packet integrity check  
   - heartbeat monitoring (рекомендовано)  
   - offline mode handling (**при OFFLINE → принудительный переход в HOME**)

## 🔌 ПРОТОКОЛ (фиксированный)

### Базовый формат (одиночный пакет):
<VER=1;DEVICE=GAMEDECK;GAME=RDR2;SESSION=01:42:18;STATE=RUNNING;FPS=118;CPU=54;GPU=67;RAM=41>


### Групповой пакет (для RECENT GAMES):
<LIST=RECENT;COUNT=3>
<GAME=RDR2;TOTAL=10:23;LAST=2025-03-15;WEEK=02:15;MONTH=08:42>
<GAME=CS2;TOTAL=05:12;LAST=2025-03-14;WEEK=01:30;MONTH=03:44>
</LIST>


### Команды Handshake:
- ПК → ESP32: `<CMD=PING>`  
- ESP32 → ПК: `<CMD=PONG;DEVICE=GAMEDECK;VER=1>`

### Ограничения протокола:
- **максимальная длина DATA-пакета:** 256 байт  
- **максимальная длина LIST-пакета:** 512 байт (при необходимости – авто-фрагментация с `PART=1/2`)  
- **При фрагментации:** если `</LIST>` не получен в течение 500 мс после последнего байта – весь пакет отбрасывается, частичные списки не отображаются  
- рекомендуемая частота обновления: 1–5 Гц (жёсткий лимит 10 Гц)  
- принимаются только полные пакеты  
- групповые пакеты буферизируются до закрывающего `</LIST>`

### Heartbeat (рекомендовано):
- при отсутствии активности игры ПК может отправлять `<STATE=IDLE;HB=1>` раз в 1–2 секунды  
- отсутствие любых пакетов >5 секунд → переход в `OFFLINE`

### Версионирование:
- `VER` обязателен в первом пакете после подключения  
- несовместимые версии игнорируются

## 🖥 PHASE 2 — ESP32 UI FOUNDATION
- Реализация state machine (BOOT, HOME, MONITOR, STATS, RECENT GAMES, DETAIL VIEW, SETTINGS)  
- Подключение 5 тактовых кнопок: LEFT (GPIO26), RIGHT (GPIO27), UP (GPIO14), DOWN (GPIO32), CENTER (GPIO13)  
- Антидребезг программный (фильтр 30–50 мс), INPUT_PULLUP, подключение к GND  
- Переключение экранов по LEFT/RIGHT (кольцевое)  
- Навигация UP/DOWN в списках и меню  
- Отображение статических UI-заглушек (мок-данные)  
- **DEBUG MODE:** удержание кнопки CENTER при загрузке (≥2 с на boot-экране) → вывод отладочной информации в Serial  
- **Правило CENTER:** короткое нажатие = контекстное действие; долгое (1.5–2 с) = глобальный вход/выход из SETTINGS (из любого состояния)

## 🔌 PHASE 4 — SERIAL + PROTOCOL CORE
**Цель:** первый рабочий пайплайн ПК ↔ ESP32

### ПК:
- Формирование простых пакетов `<VER=1;...>`  
- Отправка через Serial (автоматическое обнаружение порта через PING/PONG)  
- Соблюдение рекомендуемой частоты 1–5 Гц (макс. 10 Гц)  

### ESP32:
- Буферизированный последовательный приём (буфер ≥1024 байт)  
- **Парсинг только после получения `>`**  
- Валидация пакетов (начинается с `<`, заканчивается `>`)  
- Проверка `VER`  
- Отслеживание потери связи → переход в `OFFLINE`  
- **При OFFLINE:** принудительный переход в состояние **HOME** (не оставлять в SETTINGS или DETAIL VIEW)  
- **Восстановление:** при появлении пакетов — автоматический возврат на **последний активный экран** до потери связи

**Результат:** первый рабочий пайплайн (PC → ESP32).  
*KEY MILESTONE: `PHASE 4 = FIRST WORKING PIPELINE`*

## 🌡️ PHASE 5 — TELEMETRY
- Интеграция LibreHardwareMonitor (или OpenHardwareMonitor)  
- Получение: CPU температура (°C), GPU температура (°C), RAM использование (%)  
- При недоступности параметра → передача `-1`, ESP32 показывает `--`

---

## 📊 PHASE 6 — STATISTICS CORE (только ПК)
- Файл `games.json` на ПК  
- Хранение: `total_time`, `weekly_time`, `monthly_time`, `last_played`  
- Еженедельное/ежемесячное обнуление соответствующей статистики  
- Передача на ESP32 общих данных для экрана `STATS` (время за неделю/месяц, количество игр)  
- **ESP32 не имеет своей копии статистики – только отображает то, что прислал ПК**

## 🎮 PHASE 7 — RECENT GAMES + DETAIL VIEW UI (UI + списки)

### ПК:
- Формирование группового пакета `<LIST=RECENT;COUNT=N>...` на основе `games.json`  
- Сортировка по `last_played` (свежие сверху), ограничение до 10 записей  
- ПК — **единственный источник истины** для списка игр  
- ПК обязан отправлять обновлённый LIST-пакет с периодичностью (например, каждые 5–10 секунд) независимо от текущего экрана ESP32, чтобы данные в DETAIL VIEW были актуальными при открытии.

### ESP32:
- Приём и парсинг группового пакета (буфер ≥1024 байт)  
- **Если пакет не завершён `</LIST>`** (например, обрыв) → игнорировать полностью, не отображать частичные данные  
- Отображение списка на экране `RECENT GAMES`  
- **ESP32 никогда не кеширует список между пакетами** – обновляется только при получении нового корректного LIST  
- Никакой пересортировки или фильтрации на ESP32  
- Навигация: UP/DOWN по списку с подсветкой активного элемента, скролл  
- **Открытие DETAIL VIEW:** короткое CENTER на выбранной игре – берётся **snapshot** данных из последнего LIST-пакета (не live-обновление)  
- **Отображение DETAIL VIEW:** любые поля `-1` (CPU, GPU, RAM, FPS) показываются как `--`  
- **Выход из DETAIL VIEW:** LEFT — возврат в RECENT GAMES (в этом состоянии LEFT не переключает экран по кольцу); долгое CENTER — глобальный переход в SETTINGS
- Если список пуст – отображать «Нет данных»

## ⚙️ PHASE 10 — SETTINGS v1.0 (только критическое)

**Вход/выход:** долгое нажатие CENTER (1.5–2 с) из любого состояния (включая DETAIL VIEW).

**В состоянии SETTINGS кнопки LEFT и RIGHT заблокированы** — не переключают экраны. Работают только UP/DOWN/CENTER.

**Пункты меню (строго v1.0):**
- Connection Status (диагностика: состояние связи, версия протокола, время последнего пакета)
- Restart Device (программная перезагрузка ESP32)
- About (FW:1.0, ESP32, ST7789V)

> Примечание: SETTINGS — это **панель управления устройством**, а не игровой статистикой. Ожидания пользователя не должны включать управление играми.

**Что НЕ входит в v1.0 (перенесено в v1.1):**
- Brightness (регулировка яркости)
- Display Settings (анимации, загрузочный логотип)
- Reset Device (сброс локальных настроек ESP32)

## 🚀 PHASE 11 — RELEASE 1.0

### Обязательные требования (критерии готовности):
- [x] ESP32 загружается ≤4 с, показывает логотип и прогресс  
- [x] ПК находит устройство через Handshake (PING/PONG)  
- [x] Определяется активная игра, отображается таймер сессии (время с ПК)  
- [x] Переключение экранов: HOME, MONITOR, STATS, RECENT GAMES, DETAIL VIEW, SETTINGS  
- [x] Экран RECENT GAMES: список от ПК, прокрутка UP/DOWN, открытие DETAIL VIEW (CENTER → snapshot; выход LEFT или долгое CENTER → SETTINGS)  
- [x] Мониторинг CPU/GPU/RAM работает (или показывает `--`)  
- [x] Протокол: DATA и LIST пакеты корректно обрабатываются, лимиты соблюдены, частичные LIST игнорируются  
- [x] Offline-режим: при потере связи >5 с – "PC OFFLINE", при восстановлении возврат на последний активный экран  
- [x] Кнопки: антидребезг работает, короткое и долгое CENTER различаются корректно  
- [x] Меню SETTINGS v1.0 работает (Connection Status, Restart, About)  
- [x] DEBUG MODE: вывод отладочной информации в Serial  
- [x] Буфер ESP32 ≥1024 байт, парсинг только после `>`  
- [x] Нет критических зависаний (тест 24 часа)
